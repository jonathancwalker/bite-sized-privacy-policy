# Reading modes and featured-policy cache — November 18, 2026

The user reported that full-policy decomposition takes too long and creates too many cards. They proposed a faithful, granular “lawyer mode,” a more intent-focused plain-language “user mode,” and saved results for the homepage's familiar policies so repeat visitors need not wait or repeat model calls. They asked to examine the current system, try changes in a worktree, and consider merging only after seeing how it feels. Source: current project conversation, November 18, 2026.

The existing pipeline made sequential model requests over bounded source groups and turned nearly every substantive unit into one or more cards. The November 17 real-policy audit recorded 179 Meta and 121 TikTok US cards in its final detailed runs. The current project files were untracked on `main`, so Codex copied the exact working state into a separate `codex/reading-modes-cache` worktree before making changes; `main` remains untouched.

The first worktree iteration offered a mode picker after source preview. User mode selected at most two source-linked takeaways per smaller group and marked the overview as selective, with a direct full-policy view. Lawyer mode retained comprehensive cards and source fallbacks. Model groups ran concurrently (maximum four). Codex initially tried a local disk cache for featured imports and analyses.

The live generation returned 21 Meta, 12 TikTok US, and 30 YouTube/Google user-mode cards in 29.5, 18.5, and 36.6 seconds respectively. Detailed mode returned 174, 121, and 291 cards in 68.1, 38.6, and 69.0 seconds. These are one-run model generation times, not repeat-visit latency. Chrome inspection of the interim cache version confirmed Meta's 21-card overview, a notice that 60 source units were not summarized, and a source-linked first claim.

The user then corrected the implementation direction: “instead of actually caching, can we just save them so we can go directly to them... caching isn't necessary.” Codex removed the runtime cache, saved the three fetched policies and both analysis modes as static, dated JSON snapshots, and changed homepage tiles to open the saved user overview directly. A mode change uses the saved lawyer analysis. A deliberate refresh command regenerates snapshots; they do not update on a visitor request. In a fresh Chrome origin, one click from the homepage opened Meta's 21-card user overview, and the saved lawyer mode opened with 174 cards; no model run was needed. The user overview remains open locally for evaluation. The hosted Site remains separate. The final test suite passed 41/41 and the static build copied all three files. See [E07](../experiments.md#e07--reading-modes-and-featured-policy-cache).

This prototype tests pacing and technical latency. It does not establish that selected takeaways cover the most important issues for every reader, or that any paraphrase is legally faithful. The user's proposed naming, rationale, and saved-results correction are preserved; the selective grouping, concurrency, snapshot format, and UI implementation are Codex's working choices for review.
