# Reading-mode placement — November 18, 2026

The user asked whether user versus lawyer mode belongs as a pill toggle on the homepage or after a policy is chosen or supplied. Current conversation is the source.

Codex's proposal: keep the homepage focused on choosing a policy and default featured policies to the short user overview. For an added policy, ask for reading depth after the source preview, just before analysis, when the consequence of the choice is concrete. Keep a clearly labeled way to switch depth from the overview or review without returning home. A homepage toggle would add an abstract choice before the reader has seen a document and compete with the primary entry action. The existing saved-policy branch already opens featured policies directly into user mode and exposes “Change reading mode” from the overview; its own-policy preview has a mode choice. User feedback on this proposed placement is still pending.

The user then rejected the sequence in which a policy choice appears to start a review before reading depth is chosen. They proposed progressive disclosure on the homepage: select a policy, reveal the mode choice with a scroll or fade, then show the corresponding result. The local iteration now treats policy selection as the first step. Featured choices reveal reading depth before opening a saved analysis; the own-policy disclosure reveals reading depth before upload, paste, or URL input. The extracted-text preview shows the selected mode with a Change action. Switching after reactions still requires a clear replacement decision because the card sets differ.
