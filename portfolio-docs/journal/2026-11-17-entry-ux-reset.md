# Entry experience reset

The user said the current interface looks “very AI” and asked for a ground-up UX rethink, starting with the policy entry screens. Their proposed hierarchy is a narrow, quiet first screen headed “Privacy policies, bite-sized,” with three familiar policies that resolve the cold start problem and a “put in my own” path. That path should reveal only Upload, Paste, and URL tabs; Upload should support drag-and-drop and a system file chooser. They emphasized progressive disclosure and constrained one- or two-column layouts. Source: current project conversation, November 17, 2026.

The attached “Insert Photo” screenshot is a structural reference for tabs above a large dashed drop zone and a chooser action, not an aesthetic direction. It is user-provided third-party interface imagery; no publication or reuse rights are assumed. Before this iteration, the local entry screen used a broad two-column hero and panel, decorative preview card, four equally weighted input buttons, a catalog select, a sample action, and several explanatory paragraphs. The baseline is captured in [the prior intake screenshot](../assets/exports/2026-11-17-flow-01-intake.jpg). The planned mock changes the entry structure while retaining the existing import, preview, and model plumbing for click-through testing. The three featured policies are an assistant implementation choice until the user selects exact defaults.

The local mock now uses a narrow landing screen and a separate own-policy screen with Upload, Paste, and URL tabs. The drop zone supports a chooser or drag/drop; selection shows the filename and waits for Continue. The extracted-text check is also constrained to one column. The existing claim and report plumbing remains attached. See [D07](../decisions.md#d07--replace-the-intake-dashboard-with-two-focused-screens) and the [new screenshots](../assets/index.md).

A read-only critique of the first screenshots identified the own-policy action falling too low when a review was saved, external-link-looking starter arrows, validation and focus needs, and tab keyboard behavior. Codex tightened spacing, used right arrows, validated selected files early, restored focus, and added roving tab focus with arrow keys. The final local browser pass reached the report from a synthetic uploaded TXT file, and paste and URL imports reached source check. See [E05](../experiments.md#e05--focused-entry-flow). The downstream screens still need a visual pass; the test document also exposed a model claim about its title heading, which should be filtered or prevented in a later output-quality pass.
