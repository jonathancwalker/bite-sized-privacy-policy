# Intelligent intake and decomposition tooling

The user narrowed product scope to privacy policies and asked for common policy selection, arbitrary policy URLs, pasted text, and PDF/DOCX/TXT/RTF import. They then made intelligent LLM decomposition and benchmarks an explicit requirement, while reserving the visible UX for later thinking. They authorized a local OpenAI key from the ad-detection project for experiments. Source: current project conversation, November 17, 2026.

Codex built a separate command-line intake and decomposition layer, preserving the existing private site during UX exploration. A smaller agent researched official policy URLs and regional variants; another built/tested file extraction; another built/tested source-first decomposition and later critiqued the integrated LLM path. The main agent implemented URL retrieval, catalog/CLI, structured model calls, validation, benchmarks, and fixes from critique.

The first live comparison gave both Sol and Luna exact quote ranges in five synthetic cases. This exposed a measurement gap: matching quotes did not test paraphrase accuracy. The record and UI integration plan now call accepted claims unverified paraphrases. A real Anthropic policy smoke test and an embedded-instruction case add evidence, without establishing broad reliability. OpenAI's public page blocked command-line fetch with HTTP 403; that failure is preserved as a retrieval limit.

See [decision D05](../decisions.md#d05--make-decomposition-source-grounded-and-model-assisted), [experiment E03](../experiments.md#e03--intake-and-llm-decomposition-benchmark), and [tooling guide](../../tooling/README.md). No key value or private policy text is retained here. The existing user-facing browser flow still uses the earlier parser.

Later, the user asked which tooling could advance while they work out the UX. The next proposed priority is a small, human-reviewed set of real policy excerpts and a local scoring harness for missing conditions, unsupported paraphrases, omitted clauses, context use, and claim size. Follow-on proposals are cross-section definition/exception linking, policy snapshot and change tracking, extraction-quality checks for uploads, and model cost/latency/error comparison. These are proposals, not accepted product decisions or measured outcomes. The proposal follows the current evidence gap: exact quote coverage is established on limited cases, while semantic fidelity is not.
